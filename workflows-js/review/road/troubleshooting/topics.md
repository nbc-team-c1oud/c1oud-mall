# 트러블슈팅 회고 토픽 목록

> 도메인 경계 없이 **문제 유형** 중심으로 분류한다.
> 기술 버그부터 관계 갈등, 작업 관성까지 — "막혔거나 틀렸거나 힘들었던" 모든 것이 대상.
> `[ ]` = 미작성 / `[x]` = 완료

---

## 기술 디버깅 (Technical Debugging)

> 코드·시스템·환경이 예상과 다르게 동작한 경험

- [ ] **직렬화 함정** — `@JsonInclude(NON_NULL)` 없이 null 필드가 body에 포함되어 PG 호출이 틀렸던 경험 (또는 비슷한 유형)
- [ ] **트랜잭션 경계 오해** — `@Transactional`이 예상대로 묶이지 않아 데이터 불일치가 생긴 경험
- [ ] **Spring Bean 충돌 / 순환 참조** — 앱이 뜨지 않아 원인을 찾는 데 시간이 걸린 경험
- [ ] **JPA N+1** — 쿼리가 폭발한 걸 언제, 어떻게 발견했나
- [ ] **환경 불일치** — 로컬은 되는데 CI/배포 환경에서 터진 경험 (H2 vs MySQL, application.yml 차이 등)
- [ ] **포트 충돌 / 외부 서비스 모킹 실패** — `RestTemplate` / `WebClient` 테스트에서 mock server가 예상 URL을 안 받은 경험
- [ ] **예외가 삼켜진 경험** — try-catch나 프레임워크 내부에서 에러가 사라져서 원인 찾기 어려웠던 경험

---

## 테스팅 함정 (Testing Pitfalls)

> 테스트가 통과했는데 실제로 틀렸거나, 반대로 테스트가 가리키는 게 뭔지 몰랐던 경험

- [ ] **false-positive 테스트** — 테스트가 통과했지만 실제 동작은 틀렸던 경험. 왜 테스트가 현실을 못 잡았나?
- [ ] **mock과 실제 구현 괴리** — mock을 믿었더니 prod에서 다르게 동작한 경험
- [ ] **`verify` 인자 오류** — 시그니처가 바뀌었는데 `verify`가 낡은 인자로 통과했던 경험
- [ ] **테스트 순서 의존성** — 다른 테스트가 전제를 건드려서 특정 조건에서만 실패한 경험
- [ ] **무엇을 테스트해야 하는지 몰랐던 경험** — 구현을 먼저 하고 테스트를 끼워 맞추다가 무의미한 테스트가 생긴 경험
- [ ] **슬라이스 테스트 범위 판단 실수** — `@WebMvcTest`에서 필요한 Bean이 빠지거나 불필요한 게 들어가서 설정에 시간을 쏟은 경험

---

## 설계 교착 (Design Deadlock)

> 어떻게 설계할지 결정을 못 해서 멈춘 경험

- [ ] **과설계(over-engineering) 함정** — 아직 필요하지 않은 추상화를 먼저 만들려다 진행이 멈춘 경험
- [ ] **분석 마비(analysis paralysis)** — 두 가지 방식의 트레이드오프를 계속 비교하다가 아무것도 안 한 경험
- [ ] **도메인 경계 불명확** — 어떤 개념이 어느 BC에 속하는지 판단하기 어려워서 설계가 흔들린 경험
- [ ] **외부 API 의존성 설계** — PortOne 같은 외부 API를 어디에 격리할지 결정 전에 구현이 엉킨 경험
- [ ] **리팩토링 vs 일단 동작** — 지금 당장 동작하게 할지 먼저 깔끔하게 만들지 사이에서 판단이 늦어진 경험

---

## 작업 관성 (Work Inertia)

> 잘못된 방향인 걸 알면서도 계속한 경험, 또는 멈추지 못한 경험

- [ ] **매몰 비용 함정** — "이미 여기까지 했으니까"라는 이유로 잘못된 구현을 계속 이어간 경험
- [ ] **방향 전환 시그널을 무시한 경험** — 뭔가 이상하다는 느낌이 있었지만 계속 밀고 나간 경험, 그 결과
- [ ] **완벽주의로 인한 지연** — "조금만 더 고치면"을 반복하다 PR이 너무 커진 경험
- [ ] **막혔을 때 혼자 너무 오래 버틴 경험** — 물어봤다면 30분에 해결될 걸 하루를 쓴 경험
- [ ] **관성적 복붙** — 다른 코드를 참고하다가 패턴의 의도를 이해 못 하고 붙여넣은 경험
- [ ] **"일단 돌아가면 됐다" 모드** — 동작은 하지만 왜 동작하는지 모른 채 넘어간 경험, 나중에 어떻게 돌아왔나

---

## 소통 오해 (Communication Breakdown)

> 의도와 다르게 전달되거나, 상대방 의도를 잘못 이해한 경험

- [ ] **요구사항 오해** — 다 만들고 나서 "이게 아니에요"를 들은 경험, 어디서 어긋났나
- [ ] **PR 코멘트 오해** — 리뷰어 의도를 잘못 읽어서 엉뚱하게 수정한 경험
- [ ] **"당연히 알겠지" 가정** — 공유 안 해도 팀원이 알 거라 생각했다가 생긴 갭
- [ ] **기술 용어 혼선** — 같은 단어를 서로 다르게 쓰다가 설계가 어긋난 경험
- [ ] **비동기 소통의 한계** — Slack·PR 코멘트로 해결하려다 실시간 대화가 필요했던 순간

---

## 팀 관계 갈등 (Team Friction)

> 협업 과정에서 불편하거나 어색하거나 부딪혔던 경험

- [ ] **코드 리뷰에서 감정이 개입된 경험** — 피드백이 공격처럼 느껴졌거나, 내 코멘트가 그렇게 들렸을 것 같은 경험
- [ ] **기여도 불균형 인식** — 내가 더 많이 하는 것 같다거나, 반대로 적게 기여하는 것 같다는 느낌이 든 경험
- [ ] **결정 구조 불명확** — 누가 최종 결정자인지 몰라서 팀이 같은 논의를 반복한 경험
- [ ] **암묵적 기대의 충돌** — 명시적으로 말한 적은 없지만 서로 다른 걸 기대하고 있었던 경험

---

## 인지 편향 (Cognitive Biases)

> 내 판단이 편향되어 있었다는 걸 나중에 깨달은 경험

- [ ] **확증 편향** — 내가 옳다는 증거만 모으다가 반대 신호를 늦게 발견한 경험
- [ ] **익숙함 편향** — 알고 있는 패턴을 적용하는 게 더 나은 방법이 있었음에도 선택한 경험
- [ ] **최신성 편향** — 가장 최근에 배운 기술·패턴을 지나치게 적용한 경험 (망치를 들면 모든 게 못으로 보이는 현상)
- [ ] **낙관적 편향** — "이건 금방 끝나겠지"라고 생각했다가 3배 걸린 경험

---

## 에너지·집중력 관리 (Energy & Focus)

> 컨디션·집중력이 판단과 작업 품질에 영향을 준 경험

- [ ] **피로 상태에서 내린 결정** — 지친 상태로 설계하거나 코드를 짜서 나중에 다시 한 경험
- [ ] **멀티태스킹의 비용** — 여러 일을 동시에 처리하다 둘 다 느려진 경험
- [ ] **컨텍스트 스위칭 비용** — PR 리뷰, 슬랙 응답, 구현을 번갈아 하다가 집중이 깨진 경험
- [ ] **진전 없는 하루의 원인 분석** — 하루 종일 일한 것 같은데 실제로 완료된 게 없었던 날의 공통 패턴
